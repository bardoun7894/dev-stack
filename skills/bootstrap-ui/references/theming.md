# Theming Bootstrap 5.3 the right way

Pin `bootstrap@5.3.9` (latest on npm 2026-11-19). 6.0.0-alpha.1 is on the `next` tag (2026-10-08). It moves to CSS-variable-first theming, `@use` Sass, prefix breakpoints (`md:d-none`) and ESM-only JS. Do not use it for client work until it reaches beta.

There are two paths. Pick by whether the app has a build step.

| App | Path | Template |
|---|---|---|
| Vite / Mix / sass build | Sass variables before import | `templates/theme.scss` |
| CDN or copied `bootstrap.min.css` | `--bs-*` runtime tokens plus component overrides | `templates/bs-theme.css` |
| Admin theme (Metronic, AdminLTE) | The theme's own Sass, or one `app-ui.css` loaded last | KB [[abd/bootstrap-brand-recolor]] |

## Sass path (preferred: one place, every component follows)

- Order:
  1. `functions`;
  2. your variables;
  3. `variables`, `variables-dark`, `maps`, `mixins`, `utilities`;
  4. the components.

  Every Bootstrap variable is `!default`, so yours must come first (docs: customize/sass).
- Change colors through `$primary` and the other theme colors, not by editing `$theme-colors` key by key. If you add a theme color, add it to `$theme-colors` with `map-merge`, then add its `-text-emphasis`, `-bg-subtle` and `-border-subtle` entries, light and dark. Without them, alerts and list groups for that color have no style (docs: color-modes).
- `$font-sizes` is built from `$h1..$h6`. If you shrink headings, set `$font-sizes` yourself, or every `fs-*` utility shrinks with them. The template does this; the bug showed in the first render.
- `$min-contrast-ratio: 4.5` makes `color-contrast()` pick readable button text. Bootstrap's default `$warning` (#ffc107) gets black text. The template's darker `$warning` gets white text at 4.67:1.
- Partial imports cut size. Keep `functions`, `variables`, `variables-dark`, `maps`, `mixins`, `utilities`, `root`, `reboot`, then only the components used, then `utilities/api` last.
- Dart Sass 1.77.8 compiles 5.3.9 cleanly with `--quiet-deps`. Newer Dart Sass prints `@import` deprecation warnings for Bootstrap's own files. They are warnings, not errors, until Bootstrap 6.

Vite (Laravel):

```js
// vite.config.js: input: ['resources/sass/theme.scss', 'resources/js/app.js']
// resources/js/app.js
import * as bootstrap from 'bootstrap';   // ESM, Popper comes from @popperjs/core
window.bootstrap = bootstrap;             // only if Blade inline scripts call bootstrap.*
```

## CSS-only path (CDN apps)

`--bs-primary` alone changes almost nothing. Bootstrap 5.3.9 compiles the primary blue into 23 component rules and 3 SVG icons (checked by grepping the dist):
- `.btn-primary` and `.btn-outline-primary`;
- form focus and `:checked`;
- the form-switch focus knob;
- range thumbs;
- `.nav-pills`, `.pagination`, `.progress` and `.list-group` active states;
- `.dropdown-menu` active link;
- the accordion focus and icon;
- the `.btn-close` focus;
- `.table-primary`.

`templates/bs-theme.css` re-points every one of them to `--app-primary`.

Rules:
- Load it after `bootstrap(.rtl).min.css`, with no `!important`.
- Keep each `*-rgb` triplet equal to its hex. Bootstrap builds tints with `rgba(var(--bs-primary-rgb), a)`, so a stale triplet shows the old blue in focus rings.
- The CSS path re-brands primary, neutrals, radius, shadow, type and the info tint. Success, danger and warning buttons keep Bootstrap's colors. A full palette needs the Sass path.
- `color-mix(in srgb, ...)` derives the subtle and emphasis tints. It is supported in every current browser (Chrome 111+, Safari 16.2+, Firefox 113+).

## Color modes (dark)

- `data-bs-theme="dark"` goes on `<html>` for the whole page, or on one element to theme only that part (docs: color-modes).
- Bootstrap does not follow the OS by itself. `templates/color-mode.js` gives light, dark and auto, stored per browser. Inline it at the top of `<head>` so the page never flashes the wrong theme.
- The dark palette is its own design, not an inverted light one:
  - primary gets lighter (`#7c9cff`), so text on it and links on dark cards pass 4.5:1;
  - cards become a raised surface (`--bs-tertiary-bg`) without shadows;
  - borders get darker (`#262c38`).
- `$color-mode-type: media-query` follows the OS with no JS, but then a single component can no longer be themed on its own. Keep `data`.

## RTL (Arabic)

- Use `<html lang="ar" dir="rtl">` plus `bootstrap.rtl.min.css`, or the theme's `.rtl` bundle. Bootstrap marks its RTL support experimental. It is generated by RTLCSS, so it is complete for core components.
- Markup must use logical classes: `ms-/me-/ps-/pe-`, `text-start/end`, `float-start/end`, `border-start/end`, `rounded-start/end`, `dropdown-menu-end`, `start-0/end-0`. Physical BS4 names never flip (doctor code `bs4-class`).
- Fonts: a Latin font first means Arabic glyphs fall back to the system font. Under `[dir=rtl]`, put an Arabic UI font first: IBM Plex Sans Arabic, Noto Kufi Arabic, Cairo or Tajawal. The template does this.
- Never letter-space Arabic. It breaks the joined script. The template resets `letter-spacing` on RTL headings.
- Numbers: keep `font-monospace` or `font-variant-numeric: tabular-nums` on amount columns so digits align. Western digits are fine for Moroccan clients; follow the client's documents.
- Sass build with RTL: compile `theme.scss` twice, the second time through RTLCSS (`postcss-rtlcss` in Vite), or ship the LTR build plus `bs-theme.css` over `bootstrap.rtl.min.css`. The second option is what the kitchen-sink render used.
- Copy and microcopy in Arabic: use the `arabic-ui` skill. This skill handles the mechanics only.

## Verify every theme

```bash
python3 scripts/contrast.py compiled-theme.css                       # Sass path
python3 scripts/contrast.py templates/bs-theme.css bootstrap.min.css # CSS path over stock
python3 scripts/kitchen_sink.py --css bootstrap.min.css --css app-theme.css --out ks.html
python3 scripts/kitchen_sink.py --css bootstrap.min.css --css app-theme.css --theme dark --out ks-dark.html
python3 scripts/kitchen_sink.py --css bootstrap.rtl.min.css --css app-theme.css --dir rtl --out ks-rtl.html
```

Screenshot with Chrome headless (`--headless=new --window-size=1360,1180 --screenshot=...`) and look at the images before saying the theme is done. Both templates pass every text pair at 4.5:1 or better, light and dark (2026-11-19). Brand colors change per client, so run the check again for each client.
