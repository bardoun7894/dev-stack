## 1. What WebMCP is

WebMCP is a proposed web standard that lets a page expose structured tools (JavaScript functions and annotated HTML forms) to browser-based AI agents. The page registers tools with JSON Schema inputs, so an agent can call a page feature directly instead of clicking through the UI. The Chrome docs say it "can significantly improve the performance and reliability of agent actuation". Sources: https://developer.chrome.com/docs/ai/webmcp ; spec status: https://webmachinelearning.github.io/webmcp/

## 2. API shape

Imperative (from https://developer.chrome.com/docs/ai/webmcp/imperative-api, "WebMCPza Maker" example; the page uses `document.modelContext`):

```js
await document.modelContext.registerTool({
  name: 'toggle_layer',
  description: 'Control pizza layers (sauce, cheese). Use "add", "remove", or "toggle".',
  inputSchema: {
    type: 'object',
    required: ['layer'],
    // properties ... (truncated in the fetch summary)
  },
  execute: async ({ layer, action }) => {
    return `Performed ${action || 'toggle'} on layer: ${layer}`;
  },
});
```

- Fields: `name`, `description`, `inputSchema` (required), `execute` (required), optional `annotations` (`readOnlyHint`, `untrustedContentHint`, `consequentialHint`, `debugging`).
- Second argument: `{ exposedTo: ['https://example.com'] }` (HTTPS origins allowed to see and run the tool).
- Unregister: pass `{ signal: controller.signal }` and call `controller.abort()`. The Chrome page also lists version notes: Chrome 153 (unregister no longer cancels in-flight calls), Chrome 155 (JSON-stringified inputs deprecated), Chrome 156 (`debugging` annotation).

Declarative (from https://developer.chrome.com/docs/ai/webmcp/declarative-api). The fetch cut the example off, so only the opening tag is confirmed:

```html
<form toolname="createSupportRequest" tooldescription="Submits a request for customer support.">
```

- `toolname` and `tooldescription` register the form. Removing either unregisters it.
- Each field becomes a schema parameter. `toolparamdescription` sets a description. Without it the browser uses `<label>`, then `aria-description`.
- `toolautosubmit` lets an agent's call submit the form. `SubmitEvent.agentInvoked` is true for agent submits. The handler calls `preventDefault()` and then `respondWith(promise)` to return a result.
- Events `toolactivated` and `toolcancel` fire on `document.modelContext`. `window.ontoolactivated` is not supported from Chrome 156.

Spec (https://webmachinelearning.github.io/webmcp/): `ModelContext` methods are `registerTool(tool, options)`, `getTools(options)`, `executeTool(tool, inputObject, options)`. There is no public `unregisterTool`. Unregistration uses the `signal` abort. The spec is a "Draft Community Group Report" dated 9 October 2026, "not a W3C Standard nor on the W3C Standards Track".

## 5. Security and permission model

- Permissions Policy `tools`, default same-origin. Cross-origin iframes need `allow="tools"`; otherwise `registerTool()` rejects with `NotAllowedError`. Sources: https://developer.chrome.com/docs/ai/webmcp/secure-tools , https://github.com/webmachinelearning/webmcp
- Default visibility: "other websites or cross-origin iframes can't observe or interact with your tools." Tools are shared by default only with the owning document, same-origin documents, and built-in agents. `exposedTo` shares with listed origins. Only secure origins are supported.
- Human in the loop: tools run visibly on the page. Set `consequentialHint: true` so the agent or browser can ask for user confirmation before a significant action. Source: https://developer.chrome.com/docs/ai/webmcp/secure-tools
- Prompt injection: the Chrome docs say "it's impossible to guarantee safety inside of a large language model (LLM)". Mitigations: `untrustedContentHint` on tools that return user or external content, and narrow `exposedTo`.
- Spec section 6 covers tool poisoning, misrepresented intent, privacy over-parameterization, and private browsing: https://webmachinelearning.github.io/webmcp/
- Auth and session reuse: the secure-tools page does not say whether tools run with the user's cookies. Tools run in the owner's execution context, so a same-origin `fetch` from `execute` carries the session. This is an inference from "tools run in the owner's execution context" (explainer), not a documented statement.
- Limits: the Chrome page says the design targets local browser workflows with a human in the loop. Clients must visit the site to learn it has tools. Suggested budgets: 500 chars per tool description, 150 per parameter, 30 for names, 1.5K per output. These may change.
- Open questions listed in the explainer: multimodal I/O, streaming, output schema validation, user confirmation and elicitation, progress reporting, service workers.

## 8. Judgment

- F3 and R1: not production-ready for a general public site. It is an origin-trial, Chrome-only, draft API. No mainstream agent is confirmed to call it. The spec's own text says the design is for human-in-the-loop local workflows.
- F1: The Chrome docs and the spec use `document.modelContext`. Some secondary sources use `navigator.modelContext`. Use `document.modelContext` and feature-detect it. Recheck before shipping.
- O1 (cheapest path, both stacks): add feature-detected code that does nothing when `document.modelContext` is missing.
  - Next.js: one client component in the root layout with `useEffect`, feature detect, call `registerTool` for 1–3 read-only tools that call existing same-origin API routes. Mark them `readOnlyHint` and set `consequentialHint` on anything that changes state. No third-party polyfill in production.
  - Laravel/Blade: a `@if`-free inline `<script>` partial in the layout that feature-detects, then calls existing routes with `fetch` and the CSRF token from the meta tag. Declarative: add `toolname` and `tooldescription` to existing forms, which costs one attribute per form and is ignored by other browsers.
  - Real users on the origin trial need the trial token. Local testing needs the flag.
- Q1 (owner): Is there a site where the owner wants agent-callable actions, and is it worth a flag-only prototype now? Question for the owner, not a recommendation to ship.
